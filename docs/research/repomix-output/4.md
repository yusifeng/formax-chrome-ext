## 总体建议

这一步应该**只扩 `mcp-node-repl/browser-client.ts` 的 JS SDK facade**，继续保持外层 MCP 只暴露 `js / js_add_node_module_dir / js_reset`。当前 server 实际注册的也正是这三个工具，smoke test 也断言工具列表等于这三个名称；这与“不暴露 90 个 direct MCP tools”的约束完全一致。 

当前项目的验证状态已经很好，应把它们当作回归门：`typecheck`、`npm test`、`test:mcp-node-repl`、`test:real` 都是 passed。 现有 backend primitives 覆盖面也足够支撑下一阶段 facade：`SUPPORTED_ACTIONS` 已包含 session/tabs/events/navigation/waits/observe/locator/input/evaluate/cdp/dev logs/download/dialog/screenshot/file upload/cleanup 等动作。

# 1. 推荐 SDK object model

建议保持 `agent.browsers.get("extension")` 入口，但返回一个更结构化的 `Browser` 对象。当前 `BrowserRuntimeAgent` 已经有 `browsers.get("extension")` 和 `browsers.list()`，`BrowserClient` 目前则是一个带 mutable `state` 的 flat method bag。 下一步可以在不破坏这些旧方法的前提下，把新 facade 挂到同一个 browser 对象上。

```ts
type Agent = {
  browsers: {
    get(name: "extension"): Promise<Browser>;
    list(): string[];
  };
};

type Browser = LegacyFlatBrowserClient & {
  readonly kind: "extension";
  readonly state: { sessionId: string | null; tabId: number | null };

  tabs: BrowserTabs;
  user: BrowserUser;
  events: BrowserEvents;
  downloads: BrowserDownloads;
  dev: BrowserDev;
  capabilities: BrowserCapabilities;

  health(): Promise<HealthResult>;
  name(name: string): Promise<BrowserSession>;
  currentTab(): Promise<Tab>;
  stop(options?: { closeTabs?: boolean }): Promise<StopSessionResult>;
  finalize(options?: {
    keep?: Array<Tab | number>;
    closeRest?: boolean;
  }): Promise<FinalizeSessionResult>;

  tool(name: BrowserToolName, args?: JsonObject): Promise<BrowserToolResult<unknown>>;
};

type BrowserTabs = {
  new(url?: string, options?: { active?: boolean; timeoutMs?: number }): Promise<Tab>;
  claim(options?: { tabId?: number; active?: boolean }): Promise<Tab>;
  current(): Promise<Tab>;
  get(tabId?: number): Promise<Tab>;
  list(options?: { controlledOnly?: boolean; currentWindow?: boolean }): Promise<BrowserTabSummary[]>;
  switch(tab: Tab | number): Promise<Tab>;
  close(tab?: Tab | number): Promise<CloseTabResult>;
};

type BrowserUser = {
  claimTab(options?: { tabId?: number; active?: boolean }): Promise<Tab>;
  handoff(options?: { keep?: Array<Tab | number>; closeRest?: boolean }): Promise<FinalizeSessionResult>;
};

type Tab = {
  readonly browser: Browser;
  readonly sessionId: string;
  readonly tabId: number;
  readonly id: number;

  goto(url: string, options?: { timeoutMs?: number }): Promise<BrowserObservation>;
  reload(options?: { ignoreCache?: boolean; waitForLoad?: boolean; timeoutMs?: number }): Promise<NavigationResult>;
  goBack(options?: { waitForLoad?: boolean; timeoutMs?: number }): Promise<NavigationResult>;
  goForward(options?: { waitForLoad?: boolean; timeoutMs?: number }): Promise<NavigationResult>;

  waitForLoadState(state?: "load" | "domcontentloaded", options?: WaitOptions): Promise<WaitForLoadStateResult>;
  waitForUrl(match: string | RegExp | UrlMatch, options?: WaitOptions): Promise<WaitForUrlResult>;
  waitForSelector(selector: string, options?: SelectorWaitOptions): Promise<WaitForSelectorResult>;
  waitForText(text: string, options?: TextWaitOptions): Promise<WaitForTextResult>;

  observe(options?: ObserveOptions): Promise<BrowserObservation>;
  locator(selector: string, options?: { strict?: boolean }): Locator;

  click(target: string | { ref: string } | { x: number; y: number }, options?: ClickOptions): Promise<BrowserObservation>;
  type(text: string, options?: TypeOptions): Promise<BrowserObservation>;
  type(selector: string, text: string, options?: TypeOptions): Promise<BrowserObservation>;
  pressKey(key: BrowserKey, options?: { waitMs?: number }): Promise<BrowserObservation>;
  moveMouse(x: number, y: number, options?: { waitMs?: number }): Promise<MoveMouseResult>;
  scroll(deltaY: number, options?: ScrollOptions): Promise<BrowserObservation>;

  evaluate<T = unknown>(script: string, options?: EvaluateOptions): Promise<T>;
  cdp<T = unknown>(method: string, params?: JsonObject, options?: { timeoutMs?: number }): Promise<T>;
  screenshot(options?: ScreenshotOptions): Promise<ScreenshotResult>;
  uploadFile(ref: string, filePath: string, options?: { waitMs?: number }): Promise<BrowserObservation>;
  handleDialog(options?: { accept?: boolean; promptText?: string }): Promise<HandleDialogResult>;
  getDevLogs(options?: GetDevLogsParams): Promise<GetDevLogsResult>;
  close(): Promise<CloseTabResult>;
};

type Locator = {
  readonly tab: Tab;
  readonly selector: string;
  readonly plan: { kind: "css"; selector: string };

  waitFor(options?: LocatorWaitOptions): Promise<LocatorWaitResult>;
  click(options?: LocatorClickOptions): Promise<BrowserObservation>;
  dblclick(options?: LocatorClickOptions): Promise<BrowserObservation>;
  fill(value: string, options?: { clear?: boolean; waitMs?: number; strict?: boolean }): Promise<BrowserObservation>;
  type(value: string, options?: { clear?: boolean; waitMs?: number; strict?: boolean }): Promise<BrowserObservation>;
  press(key: BrowserKey, options?: { waitMs?: number; strict?: boolean }): Promise<BrowserObservation>;
  setChecked(checked?: boolean, options?: { waitMs?: number; strict?: boolean }): Promise<BrowserObservation>;
  selectOption(value: string | string[], options?: { waitMs?: number; strict?: boolean }): Promise<BrowserObservation>;

  count(): Promise<number>;
  textContent(): Promise<string | null>;
  innerText(): Promise<string>;
  allTextContents(): Promise<string[]>;
  getAttribute(name: string): Promise<string | null>;
  isVisible(): Promise<boolean>;
  isEnabled(): Promise<boolean>;
  boundingBox(): Promise<BrowserRect | null>;
};
```

`FrameLocator` 先只做显式 unsupported stub：

```ts
tab.frameLocator(selector: string): FrameLocator
// 当前调用任何 action/query 都抛：frameLocator is not implemented by this backend yet.
```

原因很直接：协议文档已经说明当前 locator primitive “only CSS locators in the top frame are supported”，而能力表也把 `tab.frameLocator` 标成 `not_implemented`。

# 3. 下一 PR 的优先方法清单

## Minimal useful set

这批做到后，LLM 在 `js()` 内就可以写：

```js
const browser = await agent.browsers.get("extension");
const tab = await browser.tabs.new("https://example.com");

await tab.locator("#q").fill("123");
await tab.locator("button").click();
await tab.waitForLoadState("load");
```

建议最小集合：

1. `browser.tabs.new(url?, opts?)`
2. `browser.tabs.claim(opts?)`
3. `browser.tabs.current()`
4. `browser.tabs.get(tabId?)`
5. `browser.tabs.list(opts?)`
6. `browser.tabs.switch(tabOrId)`
7. `browser.tabs.close(tabOrId?)`
8. `browser.user.claimTab(opts?)`
9. `tab.goto(url, opts?)`
10. `tab.reload/goBack/goForward`
11. `tab.waitForLoadState/waitForUrl/waitForSelector/waitForText`
12. `tab.observe(opts?)`
13. `tab.locator(selector)`
14. `locator.click/dblclick/fill/type/press/setChecked/selectOption`
15. `locator.count/textContent/innerText/allTextContents/getAttribute/isVisible/isEnabled/boundingBox/waitFor`
16. `tab.click/type/pressKey/moveMouse/scroll`
17. `tab.evaluate/cdp/screenshot/handleDialog/getDevLogs/close`
18. `browser.events.get/clear/wait`
19. `browser.downloads.list/wait`
20. `browser.capabilities.list`

## Nice-to-have set

1. `tab.saveScreenshot(path, opts?)`：纯 Node/client helper，把 current base64 写文件。
2. `browser.user.handoff({ keep, closeRest })`：包 `finalizeSession`。
3. `browser.name(name)`：包 `nameSession`。
4. `tab.uploadFile(ref, filePath)`：先 ref-only。
5. `locator.strict()` 或 `{ strict: true }`：client-side 先 `count()`，再 action。
6. `browser.events.mark()`：用 `getEvents({ limit: 1 })` 返回最新 sequence，方便 action 前建立事件 checkpoint。
7. `tab.capabilities()`：包 `getCapabilities({ scope: "tab", sessionId, tabId })`。

## Defer set

1. `frameLocator` 真实现。
2. `getByRole/getByText/getByLabel/getByPlaceholder/getByTestId` 等 semantic locators。
3. Playwright 风格 locator chaining：`locator("form").locator("button")`。
4. Popup/new-tab event model。
5. Clipboard/history/cookies/storage/network interception。
6. Full-page/clip screenshot。
7. Arbitrary keyboard modifiers。
8. 任何 UI polish、visual cursor polish、viewport controls。

# 5. 具体实现步骤

1. **保留旧 flat API，不破坏 smoke tests。**
   当前 `createBrowserClient()` 已把 `browser.openUrl()`、`browser.locatorAction()`、`browser.rawCdp()` 等 flat methods 装到同一个 object 上。 新 PR 应在这个 object 上追加 `tabs/user/events/downloads/dev/capabilities`，而不是删旧方法。

2. **抽出内部 transport。**
   把当前 `run()` / `result()` / `withDefaults()` / `rememberBrowserTarget()` 保留，但包装成内部 helper：

   ```ts
   type BrowserTransport = {
     state: BrowserState;
     run(name: BrowserToolName, args?: JsonObject): Promise<BrowserToolResult<unknown>>;
     result<T = unknown>(name: BrowserToolName, args?: JsonObject): Promise<T>;
   };
   ```

   `withDefaults` 目前会把 `state.sessionId/tabId` 注入多数 action，而 `rememberBrowserTarget` 会从 envelope/result 里更新 state。 新 `Tab` / `Locator` 方法不要依赖隐式 defaults，应显式传自己的 `sessionId/tabId`。

3. **加 `TabImpl` 和 `LocatorImpl` class。**
   `TabImpl` 构造参数是 `{ browser, transport, sessionId, tabId }`。`LocatorImpl` 构造参数是 `{ tab, selector, strict? }`。Locator 永远只保存 locator plan，不保存 DOM node/ref；这与 backend “action time resolve” 一致。

4. **实现 `BrowserTabsImpl`。**
   `tabs.new(url)` 的推荐实现：

   ```ts
   const created = await result<CreateTabResult>("browser_create_tab", { active: opts?.active });
   const tab = new TabImpl(browser, created.session.sessionId, created.tab.id);
   if (url) await tab.goto(url, { timeoutMs: opts?.timeoutMs });
   return tab;
   ```

   这样避免 `chrome.tabs.create({ url })` load timing 不确定。

5. **实现 wait result assertion helper。**
   backend wait primitives 很多是“timeout 返回成功 payload，而不是 throw”。facade 对 LLM 默认应该 throw：

   ```ts
   function assertWait<T extends { matched?: boolean; timedOut?: boolean; reason?: string }>(
     result: T,
     label: string,
     soft?: boolean
   ): T {
     const failed = result.timedOut === true || result.matched === false || result.reason === "timeout";
     if (failed && !soft) throw new Error(`${label} timed out`);
     return result;
   }
   ```

6. **移除新 object API 中的 ambiguous string target。**
   旧 flat `browser.click("...")` 使用 `looksLikeSelector()` 猜 selector/ref；新 `tab.click("...")` 一律当 CSS selector，ref 必须写 `tab.click({ ref: "e0" })`。这是 LLM ergonomics 的关键修正。

7. **加 typed handles，但不加 backend。**
   `browser.events` 包 `getEvents/clearEvents/waitForEvent`，`browser.downloads` 包 `listDownloads/waitForDownload`，`browser.capabilities` 包 `getCapabilities`，`browser.dev` 包 `getDevLogs`。这些都是当前 primitives 已有能力。

8. **加 `unsupported` stubs。**
   `tab.frameLocator()`、`browser.clipboard.read/write()` 可以存在，但调用时抛清晰错误，并建议检查 `browser.capabilities.list()`；能力表已明确 clipboard、history、semantic locator、frame locator 不可用。

9. **更新 `llm-node-repl-chat.js` system prompt。**
   当前提示词仍列 `browser.openUrl(url)`、`browser.observe()`、`browser.click({ ref })`、`browser.type(selector,text)` 等 flat 调用。 新提示词应改成 `browser.tabs.new()`、`tab.locator().fill()`、`tab.locator().click()`。

10. **只在确认不可安全组合时加 backend primitive。**
    本 PR 不需要 backend addition。下一批可考虑 `uploadFile` 支持 selector、`locatorAction` 支持 `focus/hover/clear`、`waitForNavigation`，但不要把它们混进 facade MVP。

# 6. 当前代码里的设计陷阱

1. **mutable global browser state 会污染多 tab 操作。**
   旧 client 有单个 `state.sessionId/tabId`，每次 tool result 都可能更新它。 新 `Tab` wrapper 必须显式携带 tab identity，避免 LLM 在两个 tab 之间切换时误操作 active state。

2. **`browser_get_tab` 当前不会自动带 defaults。**
   `noDefaultActions` 包含 `"browser_get_tab"`，所以旧 `browser.getTab()` 没传 session/tab 时会触发 backend “Missing tabId or valid sessionId”。 新 `browser.tabs.current()` 应主动使用 `browser.state`。

3. **string target heuristic 对 LLM 不友好。**
   `targetArg()` 用 `looksLikeSelector()` 猜测 string 是 CSS selector 还是 ref；像 `"e1"` 这种 ref 很容易被当作 tag selector。 新 object API 应要求 ref 用 `{ ref }`。

4. **wait timeout 不抛，LLM 可能继续执行。**
   `locatorWait` / selector/text waits 返回 `{ matched:false, timedOut:true }`；这适合 backend，但 SDK facade 默认应转成异常。`soft:true` 再暴露 raw result。

5. **locator strictness 和 first-match 语义要讲清楚。**
   backend action 当前基于 CSS selector 操作 first match；query 的 `count/allTextContents` 可看 all matches，但 action 不做 strict。SDK 可以提供 `{ strict:true }` 做 client-side count guard。

6. **locator chaining 不能轻率做。**
   简单拼接 `"parent child"` 不等于 Playwright locator chaining；`locator("form").locator("button")` 涉及 scope、frame、shadow DOM、strictness。MVP 不做，最多提供 `tab.locator("form button")`。

7. **frame support 目前不能伪装。**
   协议明确当前 CSS locator 只在 top frame；能力表也标 frame locator unavailable。  `frameLocator` 应抛 explicit unsupported。

8. **event/wait race。**
   对 dialog/download/navigation 这类事件，SDK 应提供 `events.mark()`：action 前读最新 sequence，action 后 `wait({ sinceSequence })`。现有 event buffer 支持 `sinceSequence` filter。

9. **raw CDP 是必要 escape hatch，但要显式“危险”。**
   `cdp` 已是 current primitive，并会 attach debugger、serialize same-tab attach、设置 timeout。 但 SDK 文档应避免 LLM 把 untrusted page text 拼进 CDP method/script。

10. **`uploadFile` 依赖最新 observation ref。**
    协议说明 `ref` 只对最新 observation 同页/同 frame 有效。 所以 `tab.uploadFile(ref,path)` 前最好示例中 always `await tab.observe()`。

# 7. 测试建议

## Unit / smoke tests

1. **MCP 外层仍只有三工具。**
   继续保留当前 smoke 断言 `["js", "js_add_node_module_dir", "js_reset"]`。

2. **facade shape smoke。**
   在 `test-scripts/mcp-node-repl-smoke.js` 里扩展现有 browser runtime shape 检查：当前已经检查 `hasOpenUrl/hasRawCdp/hasListTabs/hasLocatorAction/...`。 新增：

   ```js
   const browser = await agent.browsers.get("extension");
   return {
     hasTabs: typeof browser.tabs?.new === "function",
     hasUser: typeof browser.user?.claimTab === "function",
     hasDownloads: typeof browser.downloads?.wait === "function",
     hasEvents: typeof browser.events?.wait === "function",
     hasTabLocator: typeof browser.tabs === "object"
   };
   ```

3. **mock transport mapping test。**
   给 `createBrowserClient({ callTool })` 增加可选 dependency injection，测试：

   ```js
   const tab = await browser.tabs.new("https://example.test");
   await tab.locator("#name-input").fill("Alice");
   ```

   断言第二个或第三个 call 是：

   ```js
   {
     name: "browser_locator_action",
     args: {
       sessionId,
       tabId,
       locator: { kind: "css", selector: "#name-input" },
       kind: "fill",
       args: { value: "Alice" }
     }
   }
   ```

4. **wait 默认抛 / soft 不抛。**
   mock `browser_wait_for_selector` 返回 `{ matched:false, timedOut:true }`，断言 `await tab.waitForSelector("#x")` rejects，而 `await tab.waitForSelector("#x", { soft:true })` resolves。

5. **string target disambiguation。**
   断言 `tab.click("#submit")` 传 `selector:"#submit"`；`tab.click({ ref:"e1" })` 传 `ref:"e1"`；不支持 `tab.click("e1")` 作为 ref。

6. **state isolation。**
   mock 两个 tab：`tabA.locator("#x").click()` 与 `tabB.locator("#x").click()` 必须分别传自己的 `tabId`，不受 `browser.state.tabId` 后续变化影响。

7. **legacy compatibility。**
   旧 `browser.openUrl()`、`browser.locatorAction()`、`browser.rawCdp()` 仍存在；当前 smoke 已覆盖一部分旧方法存在性。

# 8. Backend additions：只建议小而清晰的后续项

本 PR 先不加 backend。后续小 addition 可以按这个顺序做：

1. `uploadFile` 支持 `{ selector }` 或 `{ locator }`，不再强迫 LLM 先 observe/ref。
2. `locatorAction` 增加 `focus`、`hover`、`clear`。
3. `waitForNavigation` 或 `eventCheckpoint` primitive，让 action-triggered navigation 更稳。
4. `pressKey` 支持 modifier / broader key set。
5. `screenshot` 支持 `clip` / `fullPage`。
6. `clipboard` primitive；但能力表现在明确是 unavailable，不要在 facade 中假装可用。

# 9. 最终落点

下一 PR 的核心不是“更多能力”，而是**把已验证 primitives 变成 LLM 不容易误用的对象模型**：

```js
const browser = await agent.browsers.get("extension");
const tab = await browser.tabs.new("https://example.com");

await tab.locator("#q").fill("123");
await tab.locator("button[type=submit]").click();
await tab.waitForUrl(/submitted|results/);
```

这样保留现有三工具 MCP 面、保留旧 flat API 回归兼容，同时把实际 LLM 写法从“传大 JSON 给 `locatorAction`”推进到“Tab + Locator 对象调用”。
