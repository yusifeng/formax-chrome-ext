根据 2026-06-04 上传的 Repomix 包，我建议下一阶段**不要扩 MCP 工具面**，继续保持外部只暴露 `js / js_add_node_module_dir / js_reset`；这与当前 `mcp-node-repl/server.ts` 的三个注册工具一致。 当前验证状态也已经把 `typecheck / unit / mcp-node-repl / real-browser` 都跑通，适合作为下一 PR 的回归门。

## 1. 推荐 SDK 对象模型

目标形态建议是：**保持现有 flat client 兼容，同时在 `browser-client.ts` 内叠加对象 facade**。也就是旧代码仍可运行：

```js
await browser.locatorAction({
  locator: { kind: "css", selector: "#name-input" },
  kind: "fill",
  args: { value: "Alice" }
});
```

但推荐 LLM 写成：

```js
const browser = await agent.browsers.get("extension");
const tab = await browser.tabs.new("https://example.com");

await tab.locator("#q").fill("123");
await tab.locator("button[type=submit]").click();
await tab.waitForLoadState("load");
```

建议的对象层级如下：

```ts
Agent
  browsers
    list(): string[]
    get("extension"): Promise<Browser>

Browser
  kind: "extension"
  state: { sessionId: string | null; tabId: number | null }   // 兼容现有 flat client
  tools
  tool(name, args)                                            // raw backend envelope
  health()

  tabs: BrowserTabs
  user: BrowserUser
  events: BrowserEvents
  downloads: BrowserDownloads
  capabilities: BrowserCapabilities

  // 兼容旧 flat API：openUrl / observe / click / locatorAction / rawCdp / ...

BrowserTabs
  new(urlOrOptions?)
  claim(options?)
  current()
  get(tabId)
  list(options?)
  select(tabOrId)
  close(tabOrId)

BrowserUser
  claimTab(options?)
  nameSession(name)
  finalize(options?)
  stop(options?)

Tab
  sessionId
  tabId
  info()
  bringToFront()
  goto(url, options?)
  openUrl(url, options?)          // alias
  reload(options?)
  goBack(options?)
  goForward(options?)
  waitForLoadState(state?, options?)
  waitForUrl(matcher)
  waitForSelector(selector, options?)
  waitForText(text, options?)
  observe(options?)
  locator(selector, options?)
  click(targetOrOptions?, options?)
  moveMouse(x, y, options?)
  scroll(deltaYOrOptions?, options?)
  type(textOrSelector, textOrOptions?, options?)
  pressKey(key, options?)
  evaluate(scriptOrOptions, options?)
  cdp(methodOrOptions, params?, options?)
  rawCdp(...)
  getDevLogs(options?)
  handleDialog(options?)
  screenshot(options?)
  uploadFile(refOrOptions, filePath?, options?)
  close()

Locator
  tab
  plan: { kind: "css"; selector: string }
  locator(childSelector)
  waitFor(options?)
  count(options?)
  allTextContents(options?)
  textContent(options?)
  innerText(options?)
  getAttribute(name, options?)
  isVisible(options?)
  isEnabled(options?)
  boundingBox(options?)
  click(options?)
  dblclick(options?)
  fill(value, options?)
  type(value, options?)
  press(key, options?)
  setChecked(checked, options?)
  selectOption(valueOrValues, options?)
```

`Agent.browsers.get("extension")` 已经存在，`BrowserClient` 也已经有 `kind/tools/state` 与大量 flat 方法；下一 PR 应在同一文件里把这些 flat 方法变成对象 facade 的底层调用，而不是新增 MCP tool。 当前 `setupBrowserRuntime()` 也已经会写入 `globals.agent` 与 `globals.browser`，可以继续复用这个入口。

## 2. API surface 分类

| 类别                | 可立即在 `browser-client.ts` 组合实现                                              | 需要小后端补充                                                             | MVP 简化或延后                                   |
| ----------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------- |
| Agent / Browser   | `agent.browsers.get/list`、`browser.health`、保留 flat 方法                      | 无                                                                   | 多浏览器 provider registry 暂不做                  |
| Tabs              | `tabs.new/claim/current/get/list/select/close`                             | 无                                                                   | 复杂 window/profile/context 管理延后              |
| Session / handoff | `browser.user.nameSession/finalize/stop/claimTab`                          | 无                                                                   | 更复杂的人机交接 UI 延后                              |
| Navigation waits  | `tab.goto/reload/goBack/goForward/waitForLoadState/waitForUrl`             | 可选：`waitForNavigation(action)` 若要强原子化                               | Playwright 风格 response/request 对象延后         |
| Observation       | `tab.observe({ includeAccessibility, includeDomSnapshot })`                | 无                                                                   | DOM handle / element snapshot diff 延后       |
| CSS Locator       | `tab.locator("#x")`，`Locator.click/fill/type/press/waitFor/count/text/...` | `nth/strict/has/hasText` 需要 locator plan 扩展                         | 语义 locator 先不伪装                             |
| Input / CUA       | `tab.click/moveMouse/scroll/type/pressKey`                                 | 复杂 key chord 需要更完整 key normalization                                | 拖拽、多指针、viewport 控制延后                        |
| Dev / CDP         | `tab.evaluate/tab.cdp/tab.rawCdp/tab.getDevLogs`                           | 无                                                                   | network interception、console live stream 延后 |
| Downloads         | `browser.downloads.list/wait`                                              | 无                                                                   | tab-scoped download attribution 先不做         |
| Dialogs           | `tab.handleDialog`、`browser.events.wait` 组合                                | 可选：`waitForDialog()` 便利封装                                           | Dialog 对象模型延后                               |
| Upload            | `tab.uploadFile(ref, path)` 立即可用                                           | `uploadFile` 支持 `selector/locator` 后才能自然做 `locator.setInputFiles()` | 暂不绕过 native host 文件校验                       |
| Capabilities      | `browser.capabilities.list/has`                                            | 无                                                                   | 权限模型/feature negotiation 延后                 |
| Clipboard         | 只暴露 capability，不实现方法                                                       | 需要 clipboard primitive/permission 策略                                | defer                                       |
| FrameLocator      | 可暴露 throwing placeholder                                                   | 真正 frame targeting 需要后端 frame/executionContext 支持                   | defer                                       |
| Semantic locators | 不建议客户端假实现 action                                                           | 需要 role/text/label locator engine                                   | defer                                       |

后端已经有广泛 primitive 类型，包括 `openUrl / waits / observe / locatorQuery / locatorAction / locatorWait / CUA / evaluate / cdp / downloads / dev logs / capabilities / session cleanup` 等。 CSS locator 三个核心 primitive 已在 extension 里按 action-time resolution 实现，足够支撑第一版 `Locator` facade。 但 capabilities 明确标注 `clipboard`、`tab.locator.semantic`、`tab.frameLocator` 为 `not_implemented`，所以这些不应在 MVP 里做成看似可用的高级 API。

| 对象                     | 方法                                                           | 说明                                                 |
| ---------------------- | ------------------------------------------------------------ | -------------------------------------------------- |

### Defer set

| API                                            | 原因                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| `tab.getByRole/getByText/getByLabel` action 语义 | 当前只有 CSS top-frame locator；伪实现会误导                                      |
| `FrameLocator` 真正跨 frame 操作                    | capability 已标 not implemented；需要 execution context / frame tree 支持     |
| `locator.nth/first/last/filter/has/hasText`    | 需要 locator plan 和 backend resolver 扩展                                  |
| `locator.setInputFiles`                        | 当前 `uploadFile` 只接受 observation ref；selector/locator 文件上传应走后端以保留本地文件校验 |
| clipboard                                      | capability 已标 not implemented                                          |
| network interception / request events          | 需要 CDP Network domain event buffering 与 API 设计                         |
| viewport / visual cursor polish                | 用户明确是 non-goal                                                         |

## 4. 推荐方法明细：签名、primitive、状态、边界

### Browser / Browser.tabs / Browser.user

| 方法                          | public JS signature                                                                                                                                          | underlying primitive(s)                         | 携带状态                                               | 重要边界                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| `agent.browsers.get`        | `get(name: "extension"): Promise<Browser>`                                                                                                                   | 已有 `createBrowserClient()`                      | 单例 browser client                                  | 非 `"extension"` 直接 throw                                            |
| `browser.tabs.new`          | `new(url?: string, options?: { active?: boolean; waitUntil?: "load" \| "domcontentloaded" \| "none"; timeoutMs?: number }): Promise<Tab>`；也支持 `new(options)` | `browser_create_tab`，若有 URL 则再用 `tab.goto(url)` | browser 当前 `sessionId`；返回 Tab 持有 `sessionId/tabId` | 不要直接 `createTab({url})` 后再 wait，可能错过 load；建议先 blank tab，再 `openUrl` |

`BrowserClient` 当前已经有 flat 方法，并且 `withDefaults()` 会把已记住的 `sessionId/tabId` 自动注入多数 action；对象 facade 要复用这套机制，但 `Tab` 方法必须显式传自己的 `sessionId/tabId`，不能依赖全局当前 state。 当前 `rememberBrowserTarget()` 只记 envelope/result 里的目标，这正好适合作为 Browser 默认上下文，但不能替代 Tab 的显式身份。

## 5. 精确实施步骤

1. **重构但不破坏 `browser-client.ts` 的 public flat API。** 保留 `BrowserClient` 上的 `openUrl/locatorAction/rawCdp/...`，新增 `tabs/user/events/downloads/capabilities` 属性和 `Tab/Locator` class 或 factory。现有 `createBrowserClient()` 内已经集中通过 `run/result` 调 backend，可以在这里接 facade。

2. **引入内部 helper。**

   * `coerceTabId(tabOrId)`
   * `coerceSessionId(browserOrTab)`
   * `makeTabFromEnvelope(envelope)`
   * `makeTabFromSummary(summary)`
   * `notImplemented(capabilityId, message)`
   * `normalizeUrlMatcher(input)`
   * `normalizeLocator(selectorOrPlan)`

3. **让 `createBrowserClient()` 支持测试注入。** 建议签名变为：

   ```ts
   export function createBrowserClient(options: {
     callTool?: typeof callBrowserTool;
   } = {}): BrowserClient
   ```

   默认仍用真实 `callBrowserTool`。这样 facade unit tests 不需要真实 native host。

4. **实现 `BrowserTabsFacade`。**

   * `new(url)`：先 `browser_create_tab({ sessionId, active })`，拿到 `sessionId/tabId` 后构造 `Tab`；若传 URL，再调用 `tab.goto(url)`。
   * 这样可以避免 `chrome.tabs.create({ url })` 与之后 `waitForLoadState()` 之间的 load race。
   * `claim/current/get/select/close/list` 直接映射对应 primitives。

5. **实现 `Tab`。**

   * Tab 内部永远保存 explicit `sessionId/tabId`。
   * 所有 Tab 方法都显式传 `sessionId/tabId`，不要依赖 Browser global state。
   * `toJSON()` 返回 `{ type:"Tab", sessionId, tabId }`，避免 console/JSON 输出递归或过大。

6. **实现 `Locator`。**

   * Locator 只保存 `{ tab, plan: { kind:"css", selector } }`。
   * 每次 action/query 都 action-time resolve，符合现有后端设计。
   * `locator(childSelector)` 可先实现为 `new Locator(tab, parent + " " + child)`，但文档写明这是 CSS descendant 简化，不是 scoped element handle。

7. **实现 handles。**

   * `browser.events.get/clear/wait`
   * `browser.downloads.list/waitFor`
   * `browser.capabilities.list/has/require`
   * `browser.user.claimTab/nameSession/finalize/stop`

8. **更新 LLM prompt / chat helper。**
   现在 `llm-node-repl-chat.js` 的 system message 仍教 LLM 使用 flat calls，例如 `browser.openUrl(url)`、`browser.click({ ref })`、`browser.rawCdp(...)`。 下一 PR 应把提示改成优先对象风格：

   ```js
   const browser = await agent.browsers.get("extension");
   const tab = await browser.tabs.new(url);
   await tab.locator("selector").click();
   ```

   同时保留 flat calls 作为 fallback。

9. **暂不改 extension/native-host。**
   下一 PR 仅在 `browser-client.ts` 和测试里落地。只有 `locator.setInputFiles()` 或 `getByRole/getByText` 进入 PR 时，才动 backend。

## 6. 需要小后端 addition 的 API

这些不要塞进第一波 facade，除非你愿意同时改协议和 real E2E：

1. **`uploadFile` 支持 selector/locator**

   * 当前 `UploadFileParams` 要求 `ref` 和 `filePath`。
   * 建议后端扩成：

     ```ts
     type UploadFileParams = {
       sessionId?: string;
       tabId?: number;
       ref?: string;
       selector?: string;
       locator?: { kind: "css"; selector: string };
       filePath: string;
       waitMs?: number;
     }
     ```
   * 这样可以安全实现 `await tab.locator('input[type=file]').setInputFiles(path)`，仍保留 native host 文件校验。

2. **Locator plan 支持 `index/strict`**

   * 现状 locator action/query 默认第一匹配，`count` 返回数量。
   * 建议扩：

     ```ts
     type LocatorPlan = {
       kind: "css";
       selector: string;
       index?: number;
       strict?: boolean;
     }
     ```
   * 这样才能实现 `locator.nth(2)`、`first()`、`last()`，也能给 LLM 更好的错误。

3. **Semantic locator engine**

   * `getByText/getByRole/getByLabel` 不建议客户端用 `observe()` 硬凑 action。
   * 后端应新增 locator kind：

     ```ts
     { kind: "text"; text; exact? }
     { kind: "role"; role; name?; exact? }
     { kind: "label"; text; exact? }
     ```
   * 或先仅支持 `locatorQuery/locatorWait`，action 第二阶段做。

4. **Frame targeting**

   * 需要 frame tree、execution context、`Runtime.evaluate` 指定 context、CDP DOM in frame。
   * 当前 capability 已标 `tab.frameLocator` not implemented，不应假装支持。

5. **Clipboard**

   * 当前 capability 已标 `clipboard` not implemented。
   * 需要明确权限、页面上下文与系统剪贴板边界后再加。

## 7. 设计陷阱

### 7.1 Stale session/tab state

当前 flat client 的 `state.sessionId/state.tabId` 是“最近一次成功 action”的默认目标。这个对 REPL 方便，但对象 facade 不能依赖它。`Tab` 必须持有创建时的 `sessionId/tabId`，否则多 tab 并发时一个 `browser.tabs.new()` 会污染另一个 tab 的后续动作。当前 state 注入逻辑在 `withDefaults()`，它只适合 flat API。

建议：

* `Tab` action 永远显式传 `sessionId/tabId`。
* `Tab.close()` 后设置 `closed = true`。
* 如果 backend 返回 `tabRemoved` 或 `getTab` 失败，错误提示要说“stale tab; call browser.tabs.list()”。

### 7.2 `browser.tabs.new(url)` 的 load race

`createTab({ url })` 创建页面后，再单独 `waitForLoadState()` 可能错过 load event。更安全的 facade 行为是：

1. `createTab({ url: "about:blank" })`
2. 构造 `Tab`
3. `tab.goto(url)`，让 `openUrl` primitive 在触发 `Page.navigate` 前建立 load promise。

### 7.3 Locator chaining 语义

不要在第一版暗示 Playwright 级别 locator。`locator("form").locator("button")` 如果只是拼成 `"form button"`，它不是真正的 scoped element handle，也不处理 `:scope`、shadow DOM、nth、strict mode。建议：

* 第一版只文档化为 CSS descendant convenience。
* `nth/first/last/filter/hasText` 不实现或 throw “需要 backend locator index/filter”。

### 7.4 Wait/event race

LLM 常写：

```js
await tab.locator("button").click();
await tab.waitForLoadState("load");
```

这可能在新导航前看到旧 document 已经 `complete`。建议提供：

```js
await tab.waitForUrlAfter(
  () => tab.locator("button").click(),
  { urlContains: "/done" }
);
```

或者：

```js
const wait = tab.waitForUrl({ urlContains: "/done" });
await tab.locator("button").click();
await wait;
```

更稳的 helper 可以在客户端捕获 `getEvents({limit:1})` 的 `sequence`，然后并发 action + wait。当前 real E2E 已验证 `waitForEvent` 能在 reload 后捕获 CDP event，但 facade 要把 race 模式包好。

### 7.5 Frame support

顶层 CSS locator 现在是事实能力。`FrameLocator` 可以先不挂；如果挂，所有方法应 throw：

```txt
FrameLocator is not implemented by this backend yet. Capability: tab.frameLocator.
```

不要静默落到 top frame。

### 7.6 Raw CDP escape hatch

`tab.cdp()` 非常有用，当前 `browser_cdp` schema 和类型也已存在。 但它应该被放在 `tab.cdp/rawCdp` 或 `tab.dev.cdp` 下，文档提示“trusted local tooling”。不要让 LLM 把页面文本拼到 CDP method 或 `evaluate` script 里。

### 7.7 LLM ergonomics

建议每个方法都支持“短字符串 + options”：

```js
await tab.goto(url);
await tab.waitForSelector("#ready");
await tab.locator("#name").fill("Alice");
await tab.pressKey("Enter");
```

错误消息要给下一步建议：

```txt
No active browser session. Use `const tab = await browser.tabs.new(url)` or `await browser.tabs.claim()`.
```

## 8. 测试建议

### Unit / smoke tests

1. **保留 MCP 三工具不变。** 现有 smoke test 已断言 MCP tools 只有 `js/js_add_node_module_dir/js_reset`。 下一 PR 继续保持这个断言。

2. **新增 facade shape smoke。**
   在 `test-scripts/mcp-node-repl-smoke.js` 里加入：

   ```js
   const browser = await agent.browsers.get("extension");
   return {
     hasTabs: typeof browser.tabs?.new === "function",
     hasUser: typeof browser.user?.claimTab === "function",
     hasCapabilities: typeof browser.capabilities?.list === "function",
     hasDownloads: typeof browser.downloads?.waitFor === "function",
     tabLocatorShape: typeof browser.tabs === "object"
   };
   ```

3. **`createBrowserClient({ callTool })` unit tests。**
   用 mock callTool 验证：

   * `browser.tabs.new("http://x")` 先调用 `browser_create_tab`，再调用 `browser_open_url`，且第二次带同一个 `sessionId/tabId`。
   * `tab.locator("#q").fill("abc")` 调 `browser_locator_action`，参数是 `{ sessionId, tabId, locator:{kind:"css",selector:"#q"}, kind:"fill", args:{value:"abc"} }`。
   * 两个 Tab 的 action 不被 `browser.state.tabId` 污染。
   * `browser.user.finalize({ keep:[tab] })` 会转成 `keepTabIds:[tab.tabId]`。
   * `browser.capabilities.has("tab.frameLocator")` 对 mock capabilities 返回 false。

4. **Serialization tests。**

   * `JSON.stringify(tab)` 不应爆循环。
   * `String(locator)` 输出类似 `Locator(css=#q, tab=123)`。

### Real-browser E2E

现有 real E2E 已覆盖 health/action registry、session/tabs/capabilities/events、waits、observe、CSS locator query/action/wait、click/type/key/url、evaluate/raw CDP、mouse/scroll/screenshot、upload、dialog/dev logs、download、history navigation 等。 下一 PR 应新增一个对象 facade 专用 E2E，尽量复用同一个 fixture：

```js
await test("object facade: tabs, locator, navigation", async () => {
  const browser = createBrowserClient();
  const tab = await browser.tabs.new(`${baseUrl}/`, { active: true });

  await tab.locator("#name-input").fill("Object Facade User");
  await tab.locator("#submit-button").click();
  await tab.waitForUrl({ urlContains: "Object%20Facade%20User" });

  const value = await tab.evaluate(
    `document.getElementById("submit-result").textContent`
  );
  assert(value.includes("Object Facade User"));
});
```

再加：

```js
await test("object facade: multi-tab state isolation", async () => {
  const t1 = await browser.tabs.new(`${baseUrl}/`);
  const t2 = await browser.tabs.new(`${baseUrl}/second`);

  await t1.locator("#count-button").click();
  const t2Title = await t2.evaluate("document.title");

  assert(t2Title === "Formax Second Fixture");
});
```

以及：

```js
await test("object facade: capabilities and downloads handles", async () => {
  assert(await browser.capabilities.has("tab.locator.css"));

  await tab.locator("#download-link").click();

    filenameContains: "codex-real-download",
```

## 9. 推荐 PR 边界

**PR 1：纯 `browser-client.ts` facade + tests。**

* 不改 extension/background/native-host/shared protocol。
* 不新增 MCP tools。
* 保留所有 flat methods。
* 新增 object methods。
* 更新 smoke + real E2E。

**PR 2：locator quality backend additions。**

* `locator.index/strict`
* `uploadFile` selector/locator support
* 可能加入 `getByText` 的 query/wait，但 action 可后置。

**PR 3：semantic locators / frame locator。**

* role/text/label resolver
* frame execution context
* 更接近 Playwright/Codex 语义。

这样切分风险最低：第一 PR 主要是客户端人体工学提升，依赖当前已验证 primitive；第二、第三 PR 才改变后端能力。当前后端和测试已经证明 primitive 足够支撑第一版对象 facade，不需要把 90 个直接 MCP tools 暴露给 LLM。
