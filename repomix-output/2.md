## 1. 文件定位

```txt
1.1.5_0/content-scripts/codex.js   // 真正的 cursor overlay + 动画
1.1.5_0/background.js              // moveMouse、AGENT_CURSOR_STATE、waitForArrival
1.1.5_0/images/cursor-chat.png     // 光标资源
```

补充一个小修正：`cursor-chat.png` 原图是 **46×48 PNG**，但 DOM 里按 **23×24 CSS px** 显示，外层 cursor box 是 **24×24**。

## 2. 消息协议

Codex 用的不是 `AGENT_CURSOR`，而是：

```ts
// background -> content script
{
  type: "AGENT_CURSOR_STATE",
  state: {
    cursor: {
      x: number,
      y: number,
      visible: boolean,
      animateMovement?: boolean,
      moveSequence?: number
    } | null,
    isVisible: boolean,
    sessionId: string | null,
    turnId: string | null
  }
}

// content script -> background
{
  type: "AGENT_CURSOR_ARRIVED",
  moveSequence: number,
  sessionId: string,
  turnId: string
}
```

`moveMouse({ waitForArrival })` 在 `background.js` 里只是发状态；真正等的是 content script 动画完成后回传 `AGENT_CURSOR_ARRIVED`。后台 waiter 有 **1500ms fallback timeout**，不会无限等。

## 4. 动画状态机

核心判断：

```ts
distance < 0.5px        => 直接 snap
distance <= 196px       => scoot 短距离动画
distance > 196px        => bezier 长距离动画
animateMovement === false => 直接 snap
hidden 初次显示          => 直接放到目标点，不从旧位置飞过去
```

默认 cursor 初始点不是左上角，而是：

```ts
x = viewportWidth * 0.58
y = viewportHeight * 0.55
```

## 5. 短距离：scoot

短距离不是普通 ease-out，而是一个“蹿一下”的动画。

核心行为：

```ts
axisRotation = atan2(dy, dx)
rotationTarget = clamp(dir.x * 0.75 - dir.y * 0.62, -1, 1) * 70
```

也就是说，短距离移动时它会：

```txt
1. 沿起点 -> 终点方向做 position spring
2. 按移动方向建立一条 scoot axis
3. 中途压缩/拉伸
4. 中途有一个最多约 70° 的方向摆动
5. 到达后 snap 到精确目标点
```

短距离压缩大概是：

```ts
scootStretch = 1 - 0.15 * sin(progress * PI)
```

所以中点附近压缩最明显，最低约 **0.85**。

## 6. 长距离：Bezier 候选路径

长距离会生成 **20 条候选路径**：

```txt
2 条直接 cubic path
18 条 arc path
```

配置常量大概是：

```ts
{
  arcFlow: 0.5783555327868779,
  arcSize: 0.2765523188064277,
  boundsMargin: 20,
  candidateCount: 20,
  clickAngleDegrees: -44,
  endpointHandle: 0.15,
  startHandle: 0.41960295031576633
}
```

路径生成逻辑：

```txt
startControl = start + clickTangent * startHandleDistance
endControl   = end   - clickTangent * endHandleDistance

arcPoint = midpoint
         + naturalArcNormal * arcDistance
         + clickTangent * startHandleDistance * 0.16
```

其中：

```ts
clickTangent = angleVector(-44deg)
```

arc path 是两段 cubic：

```txt
start -> arcPoint -> end
```

直接 path 是一段 cubic：

```txt
start -> end
```

## 7. 路径打分

每条候选路径会采样，每段 cubic 采样 **24 个点**，计算：

```txt
path length
angle change energy
max angle change
total turn
是否在 viewport boundsMargin=20 内
是否逆着 clickTangent 方向
是否是 arc path
```

评分近似：

```ts
score =
  length
  + excessLengthRatio * 320
  + angleChangeEnergy * 140
  + maxAngleChange * 180
  + totalTurn * 18
  + againstClickPenalty * 90
  + arcPenalty
```

其中 `arcPenalty` 是：

```ts
arc path: 45
direct path: 0
```

选择规则是：

```txt
优先选 staysInBounds 的最低分路径；
如果所有路径都越界，则选全局最低分。
```

## 8. 光标旋转跟随 tangent

长距离动画中，光标不是固定角度。每帧会从 Bezier 曲线取 tangent：

```ts
rotation = atan2(tangent.y, tangent.x) * 180 / PI + 90
```

然后用 rotation spring 平滑过去。

这就是你观察到的“沿路径 tangent 旋转”。

## 9. Spring 系统

它没有用 CSS transition，而是自己实现了 spring integrator。

固定模拟步长：

```ts
dt = 1 / 240
```

主循环用 `requestAnimationFrame`，但物理积分按 240Hz 推进。

几个关键 spring：

```ts
visibilitySpring     // 显示/隐藏，opacity、blur、scale
stretchSpring        // 长距离速度造成的压缩/拉伸
rotationSpring       // 光标主旋转
scootAxisSpring      // 短距离 scoot 轴向
scootRotationSpring  // 短距离摆动
scootStretchSpring   // 短距离压缩
positionXSpring
positionYSpring
```

典型参数：

```ts
positionSpring:      damping 0.90, response 0.19
visibilitySpring:    damping 0.86, response 0.42
stretchSpring:       damping 0.85, response 0.20
rotationSpring:      damping 0.90, response 0.12
scootProgressSpring: damping 0.94, response 0.19
scootRotationSpring: damping 0.82, response 0.055
```

长距离移动时，路径本身还有动态 response：

```ts
response = clamp(
  (0.42
   + lengthFactor * 0.22
   + complexity * 0.12
   + againstClickPenalty * 0.28
   + arcBonus * 0.04)
  * 0.7
  * arcMultiplier,
  0.12,
  2.2
)
```

## 10. 到达判断

动画完成不只是 `progress >= 1`，还要检查位置和速度：

```ts
progress >= 0.999
progressSpring.velocity < 0.01
distanceToTarget <= 0.85
abs(positionX.velocity) <= 12
abs(positionY.velocity) <= 12
```

满足后才：

```txt
1. snap 到精确目标点
2. reset stretch / scoot springs
3. motion = null
4. 发送 AGENT_CURSOR_ARRIVED
```

## 11. 可复刻的核心骨架

下面是按逻辑提炼后的结构，不是原始打包源码逐字拷贝：

```ts
function setCursorState(state) {
  const target = normalizeCursorPoint(state.cursor, viewport)
  const visible = state.isVisible !== false && state.cursor?.visible !== false
  const animate = state.cursor?.animateMovement !== false

  cursor.visibilitySpring.target = visible ? 1 : 0

  if (!state.cursor) {
    snapTo(target)
    startIdleWiggle()
    return
  }

  const dist = distance(cursor.point, target)

  if (!animate || dist < 0.5 || shouldSnapBecauseHidden()) {
    snapTo(target)
    emitArrived(state.cursor.moveSequence)
    return
  }

  if (dist <= 196) {
    startScootMotion(cursor.point, target)
  } else {
    const path = chooseBestBezierPath(cursor.point, target, viewport)
    startBezierMotion(path)
  }

  requestAnimationFrame(tick)
}
```

核心渲染 transform：

```ts
transform =
  translate3d(x - 12, y - 12, 0)
  rotate(scootAxisRotation)
  scale(1, scootStretch)
  rotate(-scootAxisRotation)
  rotate(rotation + scootRotation)
  scale(stretch * visibilityScale, visibilityScale)
```

显示/隐藏效果：

```ts
opacity = visibility
blur = lerp(5px, 0px, visibility)
visibilityScale = lerp(0.4, 1, visibility)
```

## 12. 移植时最重要的 3 件事

你如果要把这个动画复刻到自己的 overlay 里，优先搬这三层：

```txt
1. Spring integrator
   position / rotation / visibility / stretch 都靠它。

2. Motion planner
   dist <= 196 用 scoot；
   dist > 196 用 Bezier candidate scoring。

3. Arrival protocol
   只有动画真正 settle 后才发 AGENT_CURSOR_ARRIVED；
   moveSequence 用来防止旧动画误报。
```

最不像普通鼠标动画的地方，其实是 **“路径规划 + tangent 旋转 + 多个 spring 叠加”**，不是 easing 函数。
