基于 2026-06-04 上传的 repomix 包做静态分析：当前方向是对的。现有链路已经符合“LLM 只看见 `js / js_add_node_module_dir / js_reset`，浏览器能力通过 JS SDK 注入到 persistent Node kernel”的产品形态；README 与 smoke test 都显示 `node_repl` 侧只暴露三种 MCP 工具，并通过 `setupBrowserRuntime({ globals: globalThis })` 注入 `agent.browsers.get("extension")` / `browser`。 

最大缺失抽象不是 transport，也不是 Chrome extension，而是 **稳定的 Locator / Frame / Tab 对象模型**。现在 `mcp-node-repl/browser-client.ts` 只是把旧 `browser_*` RPC 包成 flat `BrowserClient` 方法，并通过 `state.sessionId/tabId` 自动补默认参数；这足够做第一版，但还不是 Codex/Playwright-like SDK。

# 1. Architecture Verdict

**结论：当前方向 sound，应该继续沿用。**

你现在的架构：

```text
LLM
  -> MCP node_repl tools only
    -> persistent Node kernel
      -> browser-client SDK
        -> agent/browserTools.ts
          -> native-host/host.ts
            -> extension/background.ts
              -> Chrome debugger / CDP / content script
```

和 README 里记录的实际 transport 一致：Agent tools 通过 `127.0.0.1:8765/rpc` 到 native host，再经 Chrome Native Messaging 到 extension/background，最后通过 `chrome.debugger / CDP` 控制真实 Chrome tab。

**最大的 missing abstraction：**

```ts
LocatorPlan + FramePlan + TabHandle
```

也就是：

```text
SDK object methods
  -> serializable action / locator plan
    -> backend primitive action
      -> CDP / chrome API
```

不要让 `locator.click()` 变成缓存某个 DOM node。它应该保存一份可序列化 plan，例如：

```ts
{
  frame: { chain: [{ strategy: "css", value: "iframe[name=checkout]" }] },
  selector: [
    { strategy: "role", role: "button", name: /pay/i },
    { strategy: "nth", index: 0 }
  ],
  strict: true
}
```

每次执行 `click/count/fill/isVisible` 时重新 resolve。这样天然解决 stale locator 的大部分问题，也能逐步扩展 iframe、shadow DOM、ARIA role、text、test id 等语义。

# 4. Recommended SDK Object Model

当前 `BrowserClient` 是 flat object，直接暴露 `openUrl/click/type/evaluate/rawCdp/...`。应该保留兼容入口，但稳定产品 API 用 class/object tree。当前 flat client 的 `withDefaults` 和 `rememberBrowserTarget` 逻辑可以迁移到 `BrowserContext`/`Tab` 对象里。

下面是 TypeScript-ish sketch，不是完整实现。

```ts
type BrowserName = "extension";

type BrowserId = string;
type SessionId = string;
type TabId = number;

type Json = unknown;

interface Agent {
  browsers: Browsers;
}

interface Browsers {
  get(name?: BrowserName): Promise<Browser>;
  list(): Promise<BrowserSummary[]>; // or sync ["extension"] initially
}

interface BrowserSummary {
  name: BrowserName;
  kind: "extension";
  connected: boolean;
}

class Browser {
  readonly name: BrowserName = "extension";
  readonly kind = "extension";

  readonly user: BrowserUserAPI;
  readonly tabs: Tabs;
  readonly capabilities: CapabilitiesAPI;

  constructor(private transport: BrowserTransport) {}

  async nameSession(name: string, options?: { sessionId?: SessionId }): Promise<void>;

  // Debug-only compatibility. Do not document as stable user API.
  async _tool(action: string, params?: Record<string, unknown>): Promise<unknown>;
  async _rawCdp(tab: Tab | TabId, method: string, params?: Record<string, unknown>): Promise<unknown>;
}

interface BrowserUserAPI {
  claimTab(options?: { tabId?: TabId; active?: boolean; sessionId?: SessionId }): Promise<Tab>;
  openTabs(options?: { currentWindow?: boolean; controlledOnly?: boolean }): Promise<TabSummary[]>;
  history(options?: { text?: string; maxResults?: number; startTime?: number; endTime?: number }): Promise<HistoryItem[]>;
}

class Tabs {
  constructor(private browser: Browser) {}

  async new(options?: { url?: string; active?: boolean; sessionId?: SessionId }): Promise<Tab>;
  async get(tabId: TabId, options?: { sessionId?: SessionId }): Promise<Tab>;
  async list(options?: { sessionId?: SessionId; controlledOnly?: boolean }): Promise<TabSummary[]>;
  async selected(options?: { sessionId?: SessionId; currentWindow?: boolean }): Promise<Tab>;
  async finalize(options?: { keep?: Array<Tab | TabId>; closeRest?: boolean; sessionId?: SessionId }): Promise<FinalizeResult>;
}

class Tab {
  readonly cua: CUAAPI;
  readonly dom_cua: DomCUAAPI;
  readonly playwright: PlaywrightAPI;
  readonly clipboard: ClipboardAPI;
  readonly dev: DevAPI;
  readonly capabilities: CapabilitiesAPI;

  constructor(
    readonly browser: Browser,
    readonly sessionId: SessionId | null,
    readonly tabId: TabId
  ) {}

  async goto(url: string, options?: { timeoutMs?: number; active?: boolean }): Promise<BrowserObservation>;
  async back(options?: NavigationOptions): Promise<BrowserObservation>;
  async forward(options?: NavigationOptions): Promise<BrowserObservation>;
  async reload(options?: { ignoreCache?: boolean; waitForLoad?: boolean; timeoutMs?: number }): Promise<BrowserObservation>;
  async close(): Promise<void>;

  async screenshot(options?: { format?: "png" | "jpeg" }): Promise<ScreenshotResult>;
  async title(): Promise<string>;
  async url(): Promise<string>;
}

class CUAAPI {
  constructor(private tab: Tab) {}

  async click(x: number, y: number, options?: PointerOptions): Promise<BrowserObservation>;
  async double_click(x: number, y: number, options?: PointerOptions): Promise<BrowserObservation>;
  async move(x: number, y: number, options?: { waitMs?: number }): Promise<void>;
  async drag(from: Point, to: Point, options?: { steps?: number; waitMs?: number }): Promise<BrowserObservation>;
  async scroll(delta: { x?: number; y?: number }, options?: { at?: Point; waitMs?: number }): Promise<BrowserObservation>;
  async type(text: string, options?: { waitMs?: number }): Promise<BrowserObservation>;
  async keypress(key: BrowserKey | string, options?: { waitMs?: number }): Promise<BrowserObservation>;
}

class DomCUAAPI {
  constructor(private tab: Tab) {}

  async get_visible_dom(options?: {
    includeAccessibility?: boolean;
    includeDomSnapshot?: boolean;
    maxNodes?: number;
  }): Promise<VisibleDomSnapshot>;

  async click(target: LocatorInput, options?: ActionOptions): Promise<BrowserObservation>;
  async double_click(target: LocatorInput, options?: ActionOptions): Promise<BrowserObservation>;
  async type(target: LocatorInput, text: string, options?: { clear?: boolean }): Promise<BrowserObservation>;
  async keypress(key: BrowserKey | string): Promise<BrowserObservation>;
  async scroll(targetOrDelta: LocatorInput | ScrollDelta, options?: ScrollOptions): Promise<BrowserObservation>;
}

class PlaywrightAPI {
  constructor(private tab: Tab) {}

  locator(selector: string, options?: LocatorOptions): PlaywrightLocator;
  getByRole(role: string, options?: { name?: string | RegExp; exact?: boolean }): PlaywrightLocator;
  getByText(text: string | RegExp, options?: { exact?: boolean }): PlaywrightLocator;
  getByLabel(text: string | RegExp, options?: { exact?: boolean }): PlaywrightLocator;
  getByPlaceholder(text: string | RegExp, options?: { exact?: boolean }): PlaywrightLocator;
  getByTestId(testId: string | RegExp): PlaywrightLocator;

  frameLocator(selector: string): PlaywrightFrameLocator;

  async evaluate<T = Json>(fnOrScript: string | ((...args: any[]) => T), arg?: Json): Promise<T>;
  async domSnapshot(options?: DomSnapshotOptions): Promise<unknown>;

  async waitForLoadState(state?: "load" | "domcontentloaded", options?: WaitOptions): Promise<void>;
  async waitForURL(url: string | RegExp | ((url: string) => boolean), options?: WaitOptions): Promise<void>;
  async waitForTimeout(ms: number): Promise<void>;

  expectNavigation(options?: {
    url?: string | RegExp;
    waitUntil?: "load" | "domcontentloaded";
    timeoutMs?: number;
  }): Promise<NavigationResult>;

  async waitForEvent(name: string, options?: WaitOptions): Promise<BrowserEvent>;
}

class PlaywrightLocator {
  constructor(
    private tab: Tab,
    private plan: LocatorPlan
  ) {}

  locator(selector: string): PlaywrightLocator;
  getByRole(role: string, options?: RoleOptions): PlaywrightLocator;
  getByText(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByLabel(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByPlaceholder(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByTestId(testId: string | RegExp): PlaywrightLocator;

  filter(options: LocatorFilter): PlaywrightLocator;
  and(other: PlaywrightLocator): PlaywrightLocator;
  or(other: PlaywrightLocator): PlaywrightLocator;
  first(): PlaywrightLocator;
  last(): PlaywrightLocator;
  nth(index: number): PlaywrightLocator;

  async count(): Promise<number>;
  async all(): Promise<PlaywrightLocator[]>;
  async allTextContents(): Promise<string[]>;

  async textContent(options?: WaitOptions): Promise<string | null>;
  async innerText(options?: WaitOptions): Promise<string>;
  async getAttribute(name: string): Promise<string | null>;
  async isVisible(): Promise<boolean>;
  async isEnabled(): Promise<boolean>;

  async click(options?: ActionOptions): Promise<void>;
  async dblclick(options?: ActionOptions): Promise<void>;
  async fill(value: string, options?: ActionOptions): Promise<void>;
  async type(text: string, options?: ActionOptions): Promise<void>;
  async press(key: string, options?: ActionOptions): Promise<void>;

  async check(options?: ActionOptions): Promise<void>;
  async uncheck(options?: ActionOptions): Promise<void>;
  async setChecked(checked: boolean, options?: ActionOptions): Promise<void>;
  async selectOption(value: string | string[] | SelectOption): Promise<string[]>;

  async waitFor(options?: { state?: "attached" | "detached" | "visible" | "hidden"; timeoutMs?: number }): Promise<void>;

  async downloadMedia(options?: DownloadMediaOptions): Promise<DownloadResult>;
}

class PlaywrightFrameLocator {
  constructor(
    private tab: Tab,
    private framePlan: FramePlan
  ) {}

  frameLocator(selector: string): PlaywrightFrameLocator;
  locator(selector: string): PlaywrightLocator;
  getByRole(role: string, options?: RoleOptions): PlaywrightLocator;
  getByText(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByLabel(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByPlaceholder(text: string | RegExp, options?: TextOptions): PlaywrightLocator;
  getByTestId(testId: string | RegExp): PlaywrightLocator;
}

interface ClipboardAPI {
  read(): Promise<unknown>;
  readText(): Promise<string>;
  write(data: unknown): Promise<void>;
  writeText(text: string): Promise<void>;
}

interface DevAPI {
  logs: {
    list(options?: { level?: string; sinceSequence?: number; limit?: number }): Promise<DevLogEntry[]>;
    clear(options?: { tabId?: TabId }): Promise<void>;
  };
}

interface CapabilitiesAPI {
  list(): Promise<CapabilitySummary[]>;
  get(name: string): Promise<CapabilitySummary | null>;
}
```

重点：`PlaywrightLocator` 保存 `LocatorPlan`，而不是保存 element handle。每次 action 都重新 resolve。这样和当前 protocol 里“ref 只对 latest observation 有效”的约束一致，也避免把页面 DOM 节点长期缓存到 SDK。protocol 已经明确 `ref` 只对同页/同 frame 最新 observation 有效，导航、刷新或失败点击后需要重新 observe。

# 5. Implementation Plan

## Stage 1 — object model + core tab/nav/action

目标：不改 extension 大结构，把 flat `BrowserClient` 包成 Codex-like object tree。

Commit-sized steps:

1. 在 `mcp-node-repl/browser-client.ts` 新增 classes：`AgentImpl`, `BrowsersImpl`, `BrowserImpl`, `TabsImpl`, `TabImpl`, `CUAAPIImpl`。
2. 保留当前 flat `browser.openUrl/click/type/...` 作为 compatibility shim，但文档主推：

   ```js
   const browser = await agent.browsers.get("extension");
   const tab = await browser.tabs.new({ url: "https://example.com" });
   await tab.cua.click(100, 200);
   ```
3. 补 `browserListTabs` wrapper/schema：后端 `extension/background.ts` 已有 `listTabs()` dispatch case，但 `agent/browserTools.ts` 和 SDK 没完整暴露。
4. 实现：

   * `agent.browsers.get/list`
   * `browser.user.claimTab`
   * `browser.tabs.new/get/list/selected/finalize`
   * `tab.goto/back/forward/reload/close/screenshot/title/url`
   * `tab.cua.click/double_click/move/scroll/type/keypress`
5. `tab.title()` / `tab.url()` 先走 `browser.evaluate("({ title: document.title, url: location.href })")` 或 `observe()`。
6. 加 SDK unit tests：只 mock `callBrowserTool`，验证 object method 到旧 action 的 mapping。
7. 加 MCP smoke test：沿用当前 `test-scripts/mcp-node-repl-smoke.js` 风格，验证三工具不变、runtime 注入后 object API 可用。当前 smoke test 已验证三工具列表和 `agent.browsers.get("extension")` 注入路径。

依赖：无 backend 大改；只补 `listTabs` 的 agent wrapper/schema。

## Stage 2 — locator facade

目标：先做 70% Playwright-like 体验，不追求完整 Playwright 语义。

Commit-sized steps:

1. 定义 `LocatorPlan`：

   ```ts
   type LocatorPlan =
     | { kind: "css"; selector: string }
     | { kind: "text"; text: string | SerializedRegex; exact?: boolean }
     | { kind: "testId"; value: string | SerializedRegex }
     | { kind: "placeholder"; value: string | SerializedRegex }
     | { kind: "label"; value: string | SerializedRegex }
     | { kind: "role"; role: string; name?: string | SerializedRegex }
     | { kind: "chain"; parts: LocatorPlan[] }
     | { kind: "nth"; base: LocatorPlan; index: number }
     | { kind: "filter"; base: LocatorPlan; filter: LocatorFilter };
   ```
2. 在 SDK 内实现 locator combinators：`first/last/nth/filter/and/or/locator/getByText/getByTestId/getByPlaceholder` 只改 plan。
3. 先用 `page.evaluate` 注入 resolver 实现：

   * `count`
   * `allTextContents`
   * `textContent`
   * `innerText`
   * `getAttribute`
   * `isVisible`
   * `isEnabled`
4. `locator.click()`：

   * resolve strict target
   * `scrollIntoView`
   * 返回 bbox center
   * 调 existing `browser_click({ x, y })`
5. `locator.fill()`：

   * resolve element
   * focus + clear + dispatch input/change
   * 调 existing `typeText` 或直接 in-page set value
6. `locator.press/type/check/uncheck/setChecked/selectOption` 先用 `evaluate + pressKey/typeText` 组合。
7. `waitFor` 先 polling `locator.query` via `evaluate`，不阻塞 backend design。
8. 加 fixture tests：CSS locator、text locator、test id、fill/click/count/isVisible。

依赖：Stage 1 `Tab.playwright` object。

## Stage 3 — DOM CUA + accessibility/DOMSnapshot

目标：把 CSS-only/evaluate-only locator 升级成可扩展 engine。

Commit-sized steps:

1. 新建 `extension/locator-engine.ts`，把 locator plan resolver 从 SDK 字符串注入迁到 extension 侧。
2. 新增 primitives：

   * `locator.query`
   * `locator.perform`
   * `locator.wait`
3. `getByRole/getByLabel` 改用 Accessibility tree + DOM node mapping，而不是手写近似规则。
4. `dom_cua.get_visible_dom()` 输出结构化 visible DOM：

   ```ts
   {
     source: "chrome_page",
     trust: "untrusted",
     url,
     title,
     viewport,
     nodes: [
       { ref, role, name, text, tagName, rect, actionable, sensitive }
     ]
   }
   ```
5. iframe MVP：

   * same-origin iframe：可通过 in-page DOM 访问；
   * cross-origin iframe：标记 unsupported，并返回清晰错误。
6. iframe full support：

   * 使用 CDP frame tree / execution contexts；
   * `FrameLocator` plan resolve 到指定 frame execution context；
   * locator action 在对应 frame 坐标系 resolve 后转换到 viewport 坐标。
7. shadow DOM：

   * 明确支持 open shadow roots；
   * closed shadow root 标记不可穿透。

依赖：Stage 2 locator plan 稳定。

## Stage 4 — clipboard/dev logs/capabilities

目标：补齐产品表面。

Commit-sized steps:

1. `tab.clipboard.readText/writeText`：

   * 优先 content script / page context Clipboard API；
   * fallback 到 extension/offscreen document 需要单独设计；
   * 对敏感页和 user-claimed tab 做显式限制。
2. `tab.dev.logs`：

   * `DebuggerManager.attachTab` 时 enable `Runtime`/`Log`，可选 `Network`；
   * event buffer 增加 `console`, `logEntry`, `networkError`, `exception`。
3. `browser.capabilities` / `tab.capabilities`：

   * 先静态 registry；
   * 根据 extension permissions、nativeConnected、tab URL scheme、debugger attach 状态动态返回。
4. `locator.downloadMedia`：

   * 定义语义：触发下载 vs 提取 media URL vs 保存 blob；
   * 初期只支持 `<img/video/audio/source>` 的 URL resolve + download wait。

依赖：Stage 1–3 object model 和 event buffer。

## Stage 5 — UX/safety polish

目标：本地开发可用，但不把 unsafe 能力误包装成稳定产品能力。

Commit-sized steps:

1. `claimTab` 加更强 UI 反馈：tab group title、overlay、session name。
2. raw CDP 改名 `_rawCdp` 或 `browser.debug.rawCdp`，默认不出现在 public docs。
3. 对 `evaluate` / `rawCdp` / clipboard / upload/download 做 capability gate。
4. 所有 observation 明确 `trust: "untrusted"`；SDK docs 强制提示 page text 不能当指令。
5. MV3 service worker lifecycle：

   * sessions/events 持久化到 `chrome.storage.session` 或 `chrome.storage.local`；
   * native reconnect 后 rehydrate；
   * debugger attach 幂等。
6. 更好的 timeout/cancellation：SDK 支持 AbortSignal，backend action 支持 bounded timeout。

# 6. Locator Method Mapping

## `locator.count()`

Stage 2 facade:

```ts
await tab.playwright.evaluate(
  serializeResolver(plan, `return resolve(plan).length`)
);
```

Stage 3 primitive:

```ts
await rpc("locator.query", {
  sessionId,
  tabId,
  plan,
  op: "count"
});
```

规则：

```text
resolve all matching elements
do not require strict mode
return number
```

## `locator.fill(value)`

Stage 2:

```text
resolve strict single element
scrollIntoView
focus
if input/textarea: value = ""; dispatch input/change
if contenteditable: textContent = ""; dispatch InputEvent
insert/type text
```

当前 backend `typeText` 已支持 selector/ref、clear、focus，再通过 `Input.insertText` 输入文本；可复用。

Stage 3：

```ts
await rpc("locator.perform", {
  plan,
  action: "fill",
  value,
  timeoutMs
});
```

要求：

```text
strict by default
password value never returned
dispatch realistic input/change events
error when element is not editable
```

## `locator.click()`

Stage 2:

```text
resolve strict element
scrollIntoView
compute bounding rect center
call browser_click({ x, y })
```

当前 `click` primitive 已可按 coordinates、selector、ref 点击，并返回 observation。

Stage 3：

```ts
await rpc("locator.perform", {
  plan,
  action: "click",
  button: "left",
  clickCount: 1
});
```

规则：

```text
strict default
retry while detaching/animating until timeout
error if hidden/disabled unless force
```

## `locator.isVisible()`

Stage 2 facade：

```text
resolve first element
check display != none
visibility != hidden
opacity != 0
rect width/height > 0
intersects viewport
```

注意：当前 `waitForSelector` 的 visible 判断已经是类似 style + rect 判断，但只支持 CSS selector。

Stage 3：

```ts
await rpc("locator.query", { plan, op: "isVisible" });
```

## `getByRole(role, { name })`

Stage 2：可以先做 approximate implementation：

```text
explicit role attr
native tag role mapping: button/a/input/select/textarea
accessible name approximate: aria-label, aria-labelledby, label, text
```

但不要声称等价 Playwright。真正可用的实现应该在 Stage 3 走 `Accessibility.getFullAXTree` + DOM mapping。当前 `observe({ includeAccessibility: true })` 已能取 truncated accessibility tree；这可作为基础，但还缺从 AX node 回到 DOM/bbox 的稳定映射。

## `frameLocator(selector)`

Stage 2：

```text
same-origin iframe only
frameLocator("iframe").locator("button") 在 evaluate 里进入 contentDocument
cross-origin iframe throws UnsupportedFrameError
```

Stage 3：

```text
use CDP Page.getFrameTree + Runtime.executionContextCreated
map FramePlan -> executionContextId
resolve locator inside that frame
convert element rect to top-level viewport coordinates
```

这是非平凡设计项，不建议在 Stage 1/2 伪装完整支持。

## `expectNavigation()`

Facade 可实现成 event + wait wrapper：

```ts
const nav = tab.playwright.expectNavigation({
  url: /submitted/,
  waitUntil: "load",
  timeoutMs: 15000
});

await locator.click();

await nav;
```

内部：

```text
record current event sequence
after action, poll getEvents({ tabId, sinceSequence })
also poll waitForURL / waitForLoadState
return when URL/load condition satisfied
```

当前 event buffer 已记录 selected CDP lifecycle events、dialog、runtime exception、download lifecycle 等；这足够做 MVP navigation waiter。

# 8. Main Design Traps

## 8.1 iframe / shadow DOM

当前 resolver 多数是 `document.querySelector` 或 main-frame `Runtime.evaluate`。这对 top-level DOM 有效，但对 cross-origin iframe 不够。Stage 2 可以明说只支持 main frame / same-origin iframe；Stage 3 再做 CDP frame execution context。不要让 `frameLocator` 在 SDK 里静默失败。

Shadow DOM 也要分层：

```text
open shadow root: can pierce
closed shadow root: cannot pierce
browser native controls: partial / unsupported
```

## 8.2 stale locators

现在 `observe` 生成的 `ref` 是 latest observation 的临时 ref；协议说明 ref 在导航、刷新或失败点击后应重新 observe。

因此：

```text
ElementRef: ephemeral
Locator: persistent plan
ElementHandle: 暂不提供
```

不要把 `window.__agentBrowserController.elements[ref]` 暴露成长期稳定对象。

## 8.3 page content prompt injection

`observe()` 返回的页面 text、labels、AX names 都是网页内容，已有协议把 observations 标成 `trust: "untrusted"`，安全规则也明确 page-returned values remain untrusted。

SDK 层要保持：

```text
page text can be data
page text cannot be instructions
page text cannot generate CDP method/script without escaping/review
```

特别是 `evaluate(script)` 和 `_rawCdp(method, params)` 不能直接拼接未可信化页面文本。

## 8.4 user tab claiming

`browser.user.claimTab()` 是产品上最敏感的 API，因为它会把用户现有 tab 纳入 agent session。MVP 至少要：

```text
block chrome://, file://, extension pages
show visible overlay/tab group
return URL/title before action
prefer explicit tabId or current active tab only
allow finalize/stop handoff
```

当前 URL policy 已阻止非 http/https。

## 8.5 raw CDP escape hatch

`cdp/rawCdp` 很有用，但不应是稳定 public SDK surface。协议也写明 raw `cdp` 是 trusted local tooling，不能把 untrusted page text 直接传入 CDP command name 或 script body。

推荐：

```ts
browser._debug.rawCdp(...)
tab._debug.rawCdp(...)
```

或需要显式 capability flag：

```ts
await browser.capabilities.get("unsafe.rawCdp")
```

## 8.6 downloads / uploads / clipboard

`uploadFile` 已在 native host 侧验证 absolute file path 且必须是 file，这个边界是对的。

后续要补：

```text
clipboard requires explicit API and permission model
downloads should return local filename only after safe state
uploads should never auto-select arbitrary local files from page text
downloadMedia must define what “media” means
```

## 8.7 service worker lifecycle

MV3 service worker 会睡眠；当前 session/events/debugger attached tabs 多为内存状态。现有 background 有 reconnect alarm 与 native reconnect 逻辑，但 session rehydration/persistence 还不是完整设计。

需要后续设计：

```text
persist sessions to chrome.storage.session/local
on startup reconnect native host
rehydrate known tab groups/tabs
debugger attach should be idempotent
event sequence may reset; SDK must tolerate
```

# 10. Open Questions

1. **Session naming semantics**
   Is `browser.nameSession("foo")` only Chrome tab group title, or also SDK-visible persistent metadata? I recommend both: update tab group title and store `{ sessionId, name }`.

2. **`agent.browsers.list()` return type**
   Current returns `["extension"]`; stable API may want summaries:

   ```ts
   [{ name: "extension", connected: true, kind: "extension" }]
   ```

   Keep sync string list only if matching target reference is more important.

3. **Locator strict mode**
   Playwright defaults many actions to strict single element. Decide whether SDK should throw on multiple matches for `click/fill`, while `count/allTextContents` allow many. Recommendation: yes.

4. **Role/label fidelity target**
   Full Playwright-compatible ARIA is a lot of work. Decide whether Stage 2 documents “approximate role/name” or hides `getByRole/getByLabel` until AX-backed implementation lands.

5. **Frame support target**
   Decide exact MVP:

   ```text
   Stage 2: main frame + same-origin iframe only
   Stage 3: cross-origin iframe through CDP execution contexts
   ```

   Avoid silently pretending full support.

6. **Raw CDP publicness**
   Should `rawCdp` remain on `browser` as now, or move to `_debug`? Recommendation: keep compatibility but document stable API as `_debug.rawCdp` only.

7. **Clipboard consent**
   Decide whether clipboard APIs require explicit user opt-in or only work on agent-created tabs. Clipboard is high-risk even in local dev.

8. **History API privacy**
   `browser.user.history` requires a privacy boundary. For MVP, either omit it or require explicit capability enablement.

9. **Service worker persistence**
   In-memory sessions/events are fine for prototype, but object SDK will feel flaky if extension SW sleeps. Decide whether Stage 5 stores session/event state in `chrome.storage.session` or accepts reset behavior.

10. **Downloads/media semantics**
    `locator.downloadMedia` needs a precise contract before implementation:

```text
click element and wait for browser download?
fetch media src to local file?
return URL only?
```

These are different security and transport problems.

---

## Final recommendation

Do **not** expand LLM tool schemas. Keep MCP as exactly:

```text
js
js_add_node_module_dir
js_reset
```

Move product surface area into `mcp-node-repl/browser-client.ts` as JS objects. Treat `agent/browserTools.ts` as an implementation detail / legacy compatibility layer. Keep `native-host/host.ts` and `extension/background.ts` as the backend primitive executor. The first strong MVP is:

```js
const browser = await agent.browsers.get("extension");
const tab = await browser.tabs.new({ url: "https://example.com" });

await tab.playwright.locator("a").first().click();
await tab.playwright.waitForLoadState("load");

return {
  title: await tab.title(),
  url: await tab.url()
};
```

The one abstraction to design carefully before coding too much is `LocatorPlan`. Everything else can be staged safely around the existing backend actions.
