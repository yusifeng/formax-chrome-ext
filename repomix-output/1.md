以下是基于两个 Repomix 包的静态审阅路线图；我没有假设本地仓库可运行。

## 1. 当前架构评估

### Formax 已经做对的部分

Formax 的总体链路已经是 Codex-like 的形状：LLM 外部只需要看到 `js`、`js_add_node_module_dir`、`js_reset` 三个 MCP 工具；`mcp-node-repl/server.ts` 也确实只注册了这三个工具，并把 JavaScript 执行放进持久 Node kernel。 README 里也把 `chat:node-repl` 描述为“只暴露三个 MCP tools”，再由模型在 REPL 内注入 `mcp-node-repl/browser-client.js`。

后端 primitive 覆盖面已经不弱。`extension/background.ts` 的 `SUPPORTED_ACTIONS` 已包含 session/tab、navigation、wait、observe、locator、CUA、evaluate、raw CDP、download、dev logs、capabilities、finalize/stop 等动作。 `shared/types.ts` 也把这些动作统一建模成 `BrowserAction`，说明协议层已经有一个较完整的类型中心。

Chrome debugger 侧的可靠性基础不错。`DebuggerManager` 已经有 per-tab attach lock、CDP command timeout、超时后强制 detach、本地 attach 状态清理，并在 attach 时启用 `Page`、`Runtime`、`DOM`、可选 `Log` domain。  这比“裸 `chrome.debugger.sendCommand`”稳很多。

Session/tab 模型已经有明确产品语义：session 有 `sessionId/name/groupId/activeTabId/tabIds/status/lastActiveAt`，并通过 Chrome tab group 做可视化归属；`startSession`、`claimTab`、`createTab`、`switchTab` 都已经在 extension 层实现。  

Observation 方向也对：当前 `observe` 返回 URL、title、viewport、可交互元素、可见文本，并默认补充 accessibility semantic tree，还支持完整 accessibility tree 和 DOMSnapshot 作为可选重型数据。 这比只返回 DOM text 更适合 LLM 选 locator。

JS browser client 的方向正确。`setupBrowserRuntime` 会把 `agent.browsers.get("extension")` 和 `globalThis.browser` 注入 REPL，全局状态记录默认 session/tab；`BrowserClient`、`TabHandle`、`LocatorHandle` 已经是对象 API，而不是把几十个 backend primitive 直接暴露给 LLM。 

测试已经覆盖关键真实路径。README 说明 `test:real` 会验证 native host、session、navigation、observation、accessibility tree、DOM snapshot、click/type/key/raw CDP、cursor overlay、scroll、screenshot、file upload、dialog、download、history navigation；也有 LLM browser agent check 和 node_repl chat。 real e2e 里也实际检查 health/action registry、session/openUrl、tabs/capabilities/events、wait、observe + a11y + DOMSnapshot。

### 与 Codex 结构对齐的地方

Codex Chrome skill 的 bootstrap 也是“通过 Node REPL `js` import `scripts/browser-client.mjs`、调用 `setupBrowserRuntime`、再 `agent.browsers.get("extension")`”，并明确只用 Node REPL `js` 控制 Chrome extension。 Formax 的 `skill/SKILL.md` 与此高度一致：要求用户自然语言交互、模型自己写 JS、仅使用三工具，并在第一次 browser action 时注入 Formax 自己的 browser runtime。

Codex 的 product prompt 把 Chrome 定义为“用于已有 Chrome 状态、登录态、cookies、extensions”的能力，并强调用户保持控制。 Formax 当前也走真实 Chrome extension + native messaging + debugger 的方向，所以未来嵌入 Electron/Formax Desktop 时可以沿用“现有浏览器状态”和“用户可见控制”的产品叙事。

Codex skill 对 browser use 的行为规范很成熟：每次动作后取最便宜的状态确认，优先 DOM snapshot 或 screenshot 之一，不重复验证同一事实；Formax skill 也已经写了 locator 优先级、wait、verification、error recovery、安全与 cleanup 规则。 

### 当前脆弱或过度简化的地方

`extension/background.ts` 目前承担了 native connection、event buffering、dispatch、session、navigation、wait、observe、locator、download、dev log、cursor 等大量职责，后续会越来越难做单元测试和故障隔离。它现在的 action switch 和结果 envelope 已经清楚，但模块边界还没有成型。

Session 状态主要是 background service worker 内存 `Map`；如果 MV3 service worker 重启，session 与 attached tab 状态容易丢失，虽然 health 会返回 sessions/attachedTabs/supportedActions/backendRevision，但还没有看到完整的持久恢复机制。 

安全策略还偏“技能说明约束”，而不是 backend 强制。Formax manifest 申请了 `debugger`、`downloads`、`tabs`、`scripting`、`nativeMessaging` 和 `<all_urls>` host permission。 但 `shared/browser-policy.ts` 目前主要只有 http/https URL 限制、key normalization、password value redaction。 raw CDP 又被标为可用 capability，这需要更强的策略中间层，避免绕过 locator/action 安全门。

Tab claiming 还需要更 Codex 化。Codex 明确要求先 `browser.user.openTabs()`，只能 claim 当前 openTabs 返回的对象，不要猜 tab id。 Formax 当前有 `claimTab` 和 `listTabs`，但从用户可见页面选择、claim provenance、release/keep 语义还不够完整。

Formax browser client 还没有 Codex 那种 `browser.documentation()` 运行时文档机制。Codex skill 要求 bootstrap 后完整读取 `await browser.documentation()`；Formax 现在主要靠静态 `skill/SKILL.md` 写 API 清单。 

## 2. 优先级路线图

### Phase 1：必须先做的稳定性与测试

1. **拆分 background action 层**
   把 `extension/background.ts` 拆成 `actions/navigation.ts`、`actions/observation.ts`、`actions/locator.ts`、`actions/downloads.ts`、`runtime/native-port.ts`、`policy.ts`。目标不是重写功能，而是让每个 action 可单测，dispatch 只做 envelope、timing、error normalization。

2. **持久化和恢复 session/tab 状态**
   在 `extension/session-manager.ts` 中用 `chrome.storage.session` 或 `chrome.storage.local` 保存 session metadata；service worker startup 时恢复并校验 tab/group 是否仍存在。`health()` 里增加 `restoredSessions`、`staleTabs`、`lastRestoreError`。

3. **tab/action 串行化与取消语义**
   加 per-tab action queue，避免同一 tab 上 `navigate/click/evaluate/observe` 互相踩状态。CDP timeout 后不仅 detach，还要让 queue 后续命令清晰失败或重试。

4. **协议/能力注册表单一来源**
   现在 action 类型、tool schemas、SUPPORTED_ACTIONS、capabilities 分散在 `shared/types.ts`、`agent/browserTools.ts`、`extension/background.ts`。建立 `shared/action-registry.ts` 或生成脚本，避免 backend 支持但 schema 漏、schema 有但 extension 不支持。

5. **安装和健康检查脚本**
   复制 Codex 的“检测脚本”思路：增加 `scripts/check-extension-installed.js` 与 `scripts/check-native-host-manifest.js`，输出 JSON，支持 fixed Web Store extension ID 和 dev override，不要求用户手动复制 ID。Codex 的安装检测会读 Chrome profile Preferences、判断 installed/enabled/disabled 状态；native manifest 检查会验证 host name、allowed origin、registry/manifest path。 

6. **browser runtime 自描述文档**
   在 `mcp-node-repl/browser-client.ts` 增加 `browser.documentation()` 和 `agent.documentation.get(name)`，覆盖 bootstrap、troubleshooting、confirmations、screenshots、downloads、file upload、raw CDP。这样 LLM 不必只依赖静态 skill，调试时也能按后端实际 capabilities 生成指南。

7. **LLM 三工具回归测试**
   扩展 `tests/scripts/llm-node-repl-chat.js`：断言模型只调用 `js/js_add_node_module_dir/js_reset`，browser runtime 只在 JS 内被 import，任务结束没有多余 tab/group，失败时有观察证据。

### Phase 2：浏览器控制能力扩展

1. **Codex-style tab lifecycle：openTabs / claim / finalize**
   增加 `browser.user.openTabs()`，返回可 claim 的 opaque tab descriptor；`browser.user.claimTab(tabDescriptor)` 不接受裸猜测 tabId。`browser.tabs.finalize({ keep: [{ tab, status }] })` 支持 `deliverable`、`handoff`、omit close/release 语义，对齐 Codex 的 tab cleanup 模型。

2. **locator 引擎升级**
   当前 Formax 已有 semantic locator facade 和测试。 下一步应把 role/name、label、placeholder、text、testId 的解析逻辑从字符串拼接表达式升级成可测试模块，支持 strict mode violation、visible fallback、shadow DOM。

3. **frameLocator MVP**
   现在 frame locator 被显式标为 unsupported，测试也确认 `supported:false`。 先支持同源 iframe 内 locator/evaluate，再考虑跨 origin frame 的 CDP target/session。

4. **更完整输入能力**
   扩展 key map、modifier、drag、select text、hover hit-target check。Codex bundled client 里有大量 CUA/Playwright injected 逻辑；Formax 不需要整包复制，但应抽其中“输入动作必须校验目标和可恢复”的思想。

5. **clipboard 与 file broker**
   capabilities 已经标 `clipboard` 未实现。 建议做虚拟 clipboard，不直接读用户系统剪贴板；file upload 改为 Formax Desktop/Electron 授权过的 file token 或 broker path，避免 LLM 任意传本地路径。

6. **observation budget 与大页面分页**
   `observe` 当前限制 5000 text、120 elements。 增加 `snapshotId`、chunked read、semantic tree budget、DOMSnapshot summary/diff，避免一次返回过大。

### Phase 3：产品/UX 打磨

1. **可见/后台模式**
   Codex in-app browser 默认后台工作，需要展示时显式 `visibility.set(true)`。 Formax 可以实现 `browser.capabilities.get("visibility")` 或 `browser.ui.setVisible()`，在 Electron 里控制 side panel / Chrome window focus。

2. **用户可停止、可理解的状态提示**
   Formax 已经有 cursor overlay、arrived acknowledgement、turnId/sessionId 绑定与 favicon badge。  下一步应把这些状态接到产品 UI：正在观察、正在点击、等待用户登录、已释放 tab、已关闭临时 tab。

3. **第一运行/修复流程**
   把 extension installed、native host manifest、host process、extension background revision、current Web Store ID/dev override 做成一页诊断，不要让用户碰 `chrome://extensions` 之外的细节。

4. **trace viewer**
   复用 `BrowserToolResult` 的 `actionId/action/sessionId/tabId/timing/result` envelope，做 JSONL trace viewer，用来调试 LLM ReAct loop、locator 失败、stale extension。协议已经定义了 action envelope 和 event buffer。

### Phase 4：可选深层平台工作

1. **多 backend abstraction**
   Codex bundled client 有 multi backend discovery 和 telemetry setup，导出的 setup function 会做 backend discovery、diagnostics、browser wrapper 初始化。 Formax MVP 先保留单 extension backend；等 Electron 内嵌浏览器出现后，再抽 `BrowserBackend` interface。

2. **本地策略服务**
   做一个 Formax policy engine：domain approval、side-effect confirmation、sensitive-data transmission gate、raw CDP denylist、download/file approval。先本地实现，后续再接企业策略。

3. **录制与重放**
   对每次 action 记录 before/after observation、screenshot hash、URL、locator plan、event buffer sequence，用于重放真实 Chrome smoke 与 LLM 回归。

4. **签名发布与自动更新**
   固定 Web Store extension ID；dev unpacked 用 config override；native host runtime 走版本化 cache + latest symlink。Formax 现在已有 `install-formax-runtime.js` 的 versioned cache 和 extension ID override 基础。

## 3. Capability gaps

### Missing runtime/backend pieces

* service worker 重启后的 session/tab/attach 恢复。
* per-tab action queue、action cancellation、long-running wait cancellation。
* native host/extension 双向版本协商，而不仅是 `backendRevision`。
* extension installed/native manifest/profile 检测脚本。
* backend policy middleware，特别是 raw CDP、downloads、file upload、existing logged-in pages。

### Missing browser API pieces

* `browser.documentation()` / `agent.documentation.get()`。
* `browser.user.openTabs()` + provenance-based `claimTab`。
* `browser.tabs.finalize({ keep: [{ tab, status }] })` 的 deliverable/handoff/omit 语义。
* visibility/background UI control。
* clipboard、history、frameLocator；capability list 里这些仍是 not implemented 或部分 unsupported。
* richer keyboard/mouse：modifier、drag、select、copy/paste virtual clipboard。

### Missing observation/locator pieces

* accessible name/role 算法还应更接近 Playwright/Codex，而不是简单 attribute/text heuristic。
* shadow DOM、iframe、cross-origin frame 支持不足。
* observation 没有 snapshot chunking/diff。
* locator strict violation 诊断可以更好，例如返回候选元素 preview。
* hit target check、遮挡检测、scroll into view 策略还需加强。

### Missing safety/permission pieces

* `<all_urls>` + `debugger` 权限很强，必须有产品层解释、runtime gating 和 action-time confirmation。
* 当前 safety 多在 skill 中声明，例如不要读 cookies/passwords/tokens、不要登录、不要购买/提交不可逆表单。 这些至少要部分落到 backend policy。
* Codex skill 对网页内容不可信、敏感数据传输、外部副作用、权限提示、CAPTCHA 都有明确确认规则；Formax 应复制规则，但用 Formax 自己的 confirmation UX。

### Missing debugging/test instrumentation

* extension build static check：manifest、icons、web accessible resources、service worker importScripts、host permissions。
* native host manifest check：host name、path executable、allowed origin、platform registry/path。
* real Chrome smoke 的 service worker restart、extension reload、stale backend、claim existing tab、finalize statuses 场景。
* LLM ReAct loop 测试：三工具约束、tab cleanup、no guessed tab id、side-effect confirmation。
* trace viewer / action event correlation。

## 5. 暂时不要复制的 Codex 复杂度

1. **不要现在复制完整 Playwright injected/bundled selector engine**
   Codex `browser-client.mjs` 是巨大的 bundled artifact，含大量 vendor/Playwright/telemetry 代码。Formax MVP 应先实现 80% 常用 locator 能力：role/name、label、placeholder、text、testId、CSS、shadow DOM、iframe MVP。

2. **不要现在做 Codex 级 multi-backend discovery**
   Codex setup 会做 multi backend discovery、diagnostics、browser wrapper 初始化。 Formax 当前只有 Chrome extension backend，过早抽象会拖慢稳定性工作。

3. **不要现在开放 history/cookies/profile 能力**
   Codex Chrome 的定位包含已有 Chrome profile 状态，但 Formax 现在更应限制读取 cookies、local storage、profile secrets。Formax capability 里 history 也是 not implemented，先保持这样。

4. **不要复制 Statsig/远端策略/复杂 telemetry 依赖**
   MVP 需要本地 action trace、错误码、health diagnostics；不需要先引入大规模遥测 SDK 或远端 policy endpoint。

5. **不要过早复制 Codex plugin marketplace 包装**
   Formax 最终要嵌入 Desktop/Electron，不必先追求 Codex plugin.json 的完整产品分发形态。先把 runtime package、native host install、fixed extension ID、dev override 做扎实。
